WHY LAKEHOUSE

창고에서 호수로,
그리고 호수가 썩는 문제

데이터 플랫폼이 지나온 순서입니다. 어디서 문제가 생겼는지 알아야 무엇을 세울지 정해집니다.

01 / 0402 / 0403 / 0404 / 04
01 1990년대 데이터 웨어하우스 사내 데이터를 정제해 쌓고 인텔리전스(대시보드)로 봅니다. 미리 정한 스키마와 ETL 이 전제라 새 데이터를 붙이는 데 시간이 걸립니다.
02 그 다음 데이터 레이크 형식을 가리지 않고 담습니다. 담기만 하고 정리가 없으면 호수가 썩습니다 — 찾을 수 없고 믿을 수 없는 데이터가 쌓입니다.
03 지금 레이크하우스 레이크의 저장 방식 위에 웨어하우스의 관리(테이블·카탈로그·품질)를 올립니다. 분석과 AI 가 같은 데이터를 봅니다.
04 추세 AI 를 위한 데이터 플랫폼 지금의 데이터 플랫폼은 AI 가 사내 데이터를 잘 쓰게 하는 쪽으로 갑니다. 에이전트가 읽을 수 있게 데이터를 준비하는 일입니다.

WHAT SALTWARE DOES

같은 플랫폼을
두 가지로 세웁니다

데이터가 어디에 있느냐에 따라 배치가 갈립니다. 클라우드에 올릴 수 있으면 퍼블릭으로, 내부망을 벗어날 수 없으면 프라이빗으로 세웁니다.

  1. 01 퍼블릭

    • 클라우드 위에 구축
    • Databricks 로 시작

  2. 02 프라이빗

    • ERP 처럼 내부망에 있는 데이터 · 온프레미스
    • 프라이빗 판은 개발 중

BEFORE YOU ASK

고객이 준비합니다

  • 지금 데이터가 어디에 어떻게 놓였는지
  • 내부망을 벗어날 수 있는 데이터와 없는 데이터의 구분
  • 먼저 쓸 업무 한 가지

먼저 확인할 것

  • 프라이빗 판은 개발 중입니다 — 내부망 구축이 급한 일정이면 시기부터 함께 확인합니다

TWO ENGINES

모을 데이터와
참조할 데이터를 함께 다룹니다

둘은 경쟁 제품이 아닙니다. 데이터가 놓인 자리가 달라서 역할이 다를 뿐이고, Sapie-Lake 가 두 쪽을 하나의 데이터 구조로 잇습니다.

LAKEHOUSE · SPARK

Databricks

Apache Spark 기반 레이크하우스입니다. 옮길 데이터를 모아 저장·처리·분석·AI 를 한 기반에서 다룹니다. Sapie-Lake 는 여기서 시작했습니다.

  • 레이크하우스
  • 데이터 파이프라인
  • 카탈로그
자세히 보기

FEDERATION · TRINO

Starburst

Trino 기반 오픈소스 조회 엔진입니다. 이미 만들어 둔 데이터를 옮기지 않고 그 자리에서 참조합니다. 내부망의 ERP 데이터도 여기에 해당합니다.

Sapie-Lake 가 두 엔진을 잇습니다

어디에 모으고 어디를 참조할지, 하나의 데이터 구조로 설계합니다.

ARCHITECTURE

데이터를 잘 써야
AI 도 잘 씁니다

일반화한 흐름입니다. 실제 구성은 데이터가 놓인 환경과 배치(퍼블릭·프라이빗)를 보고 정합니다.

  1. 01 Sources ERP · 사내 시스템 · DB · 로그 · 파일
  2. 02 Ingest Spark 로 옮길 데이터를 가져옴
  3. 03 Storage · Tables 오브젝트 스토리지(S3) 위에 Iceberg 테이블
  4. 04 Engines Databricks 레이크하우스 · Starburst 참조
  5. 05 AI · Agents 온톨로지 · 에이전트 빌더

Iceberg · Trino · Spark 는 오픈소스입니다. 제품별 라이선스는 별도로 산정합니다.

HOW WE WORK

진행 방식

  1. 01

    현황 진단

    지금 데이터가 어디에 어떻게 놓였는지, 무엇을 옮기고 무엇을 남길지 봅니다.

  2. 02

    배치 결정

    퍼블릭으로 갈지, 내부망 데이터 때문에 프라이빗이 필요한지 정합니다.

  3. 03

    구축

    가져올 데이터의 파이프라인과 테이블, 참조할 데이터의 연결을 세웁니다.

  4. 04

    운영과 AI 연계

    정리된 데이터 위에 분석과 에이전트를 올립니다.
