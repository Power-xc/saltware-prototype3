PRODUCT · SAPIE-AGENT

자료 하나 찾으려고
시스템 여러 개를 오갑니다

Sapie-Agent 는 기업용 AI 에이전트 플랫폼입니다. 데이터 조회 · 분석과 문서 질의응답(RAG)을 한 요청 안에서 잇고, 여러 전문 에이전트가 일을 나눠 맡은 뒤 결과를 모읍니다.
제공되는 에이전트를 그대로 쓰거나 부서와 업무에 맞게 직접 만듭니다. 답에는 근거가 붙고, 에이전트는 사용자가 원래 볼 수 있는 데이터 안에서만 움직입니다.

WHY SAPIE-AGENT

에이전트를 들일 때
먼저 막히는 곳

사내 데이터로 AI 에이전트를 쓰려는 조직에서 되풀이되는 네 가지입니다.

01 / 0402 / 0403 / 0404 / 04
01 데이터와 문서가 따로 놉니다 생산 실적은 시스템에, 공정 기준은 문서에 있습니다. 둘을 맞춰 보는 일은 결국 사람이 합니다.
02 업무마다 필요한 판단이 다릅니다 공정 변수를 읽는 일과 작업 표준을 찾아 답하는 일은 데이터도 판단 방식도 다릅니다. 모델 하나에 전부 맡기면 어느 쪽도 제대로 하지 못합니다.
03 AI 의 답을 검증할 길이 없습니다 RAG 로 만든 답은 겉보기로 맞고 틀림을 가리기 어렵습니다. 어떤 근거로 어떤 절차를 거쳤는지 따라갈 수 있어야 업무에 씁니다.
04 시연은 되는데 운영으로 못 넘어갑니다 파일럿 모델과 데이터 연결 하나는 성공해도, 데이터 통합과 평가 체계가 없으면 실제 업무에 들이지 못합니다.

HOW IT IS BUILT

에이전트 스튜디오 한 화면에서
만들고 운영합니다

자료 설정 · 에이전트 · 워크플로 · 로그와 감사 네 부분입니다. 워크플로는 질문에서 조회 · 지식 · 문서를 거쳐 검증 · 승인, 결과 · 보고로 이어집니다.

DATA

자료 설정

정형 데이터베이스의 접속 정보와 문서가 든 폴더를 등록합니다. 에이전트가 읽는 자료의 출처는 이 한 곳에서 관리합니다.
AGENTS

에이전트

기본 제공 에이전트를 고르거나 부서 · 업무에 맞는 에이전트를 새로 만듭니다. 기업별 데이터와 업무 규칙을 반영합니다.
WORKFLOW

워크플로

질문에서 결과까지를 단계로 잇습니다. 같은 단계에 둔 에이전트는 함께 돌고, 단계는 여섯까지 둡니다.
LOG & AUDIT

로그와 감사

워크플로가 돈 기록과 감사 로그를 남기고, 스튜디오를 쓰는 사용자를 관리합니다.

구성과 화면은 Sapie-ADP 출시 보도자료(2026.09.30)에 실린 에이전트 스튜디오 기준입니다.

BUILT-IN AGENTS

자주 쓰는 역할은
에이전트로 들어 있습니다

데이터 조회부터 보고서까지, 기본 제공 에이전트를 워크플로의 단계에 끼워 씁니다.

  • 01조회

    데이터 분석

    자연어 질문을 SQL 로 바꿔 데이터베이스를 조회합니다.

    • 여러 데이터베이스를 한 번에 묻는 연합 조회

  • 02문서

    문서 RAG 검색

    문서에서 근거를 찾아 답합니다.

    • 표가 필요한 질문이면 데이터 분석과 나란히

  • 03지식

    온톨로지 · 지식 그래프

    문서와 데이터베이스에서 업무 용어와 조인 경로를 정리해 둡니다.

    • 조회 단계 앞에 놓습니다

  • 04통제

    정책 · 보안 감사

    생성된 SQL 을 검사합니다. 개인정보 마스킹과 조인 교정도 이 자리에서 합니다.

    • 조회 단계 뒤에 놓습니다

  • 05사람

    사람 승인 (HITL)

    사람이 검토하는 단계를 워크플로 안에 둡니다.

    • 감사 다음, 보고 앞

  • 06보고

    보고서 · 대시보드

    앞 단계의 근거를 요약해 보고서로 내고, 교차 분석 대시보드를 만듭니다.

    • 워크플로의 마지막 단계

BEFORE YOU ASK

고객이 준비합니다

  • 에이전트가 읽을 데이터베이스 · 문서와 그 접근 권한
  • 먼저 맡길 업무와 답을 판정할 담당자

이럴 땐 맞지 않습니다

  • 맡길 업무를 아직 정하지 않은 경우 — 업무를 고르는 일부터 합니다
  • 근거로 쓸 데이터와 문서가 정리되지 않은 경우 — 데이터 정리가 먼저입니다

제품 화면의 기본 제공 에이전트 목록에서 옮겼습니다. 화면에는 도면 검색 · 생산관리 같은 업무 전용 에이전트도 함께 있습니다.

진행 방식

에이전트는 한 번 만들고 끝나는 결과물이 아닙니다. 답을 확인하는 방법을 시작할 때 정합니다.

  1. 01

    업무 고르기

    에이전트에게 먼저 맡길 업무 하나를 정합니다.

  2. 02

    데이터 정리

    그 업무가 쓰는 데이터와 문서를 먼저 모아 현업이 쓸 수 있게 정리합니다.

  3. 03

    에이전트와 워크플로

    기본 제공 에이전트를 고르거나 새로 만들어 단계로 잇습니다.

  4. 04

    시나리오로 검증

    업무 질문 시나리오로 에이전트의 답을 다시 확인하고, 운영하는 동안 같은 방식으로 계속 봅니다.

기술 자료 요청하기
네. Sapie-Agent 는 Sapie-ADP 의 에이전트 층이면서 따로도 도입합니다. 데이터베이스 접속 정보와 문서 폴더를 등록해 시작하고, ERP · 오브젝트 스토리지까지 연결을 넓히거나 AI 이용 정책을 걸 때 Sapie-Lake 와 Sapie-Guardian 을 더합니다.
제공되는 에이전트를 그대로 쓰거나, 기업별 데이터와 업무 규칙을 반영해 부서 · 업무에 맞는 에이전트를 직접 구성합니다. 만든 에이전트는 워크플로의 단계로 이어 붙입니다.
답과 함께 근거 데이터, 기준일, 적용 산식, 원문 출처, 데이터 갱신 시점을 보여 줍니다. 근거 데이터가 충분하지 않으면 따로 표시해 추가로 확인할 곳을 알립니다. 워크플로에 사람이 검토하는 승인 단계를 넣을 수도 있습니다.
기존 시스템의 사용자 권한과 조직별 접근 정책을 이어받습니다. 에이전트는 그 사용자가 접근할 수 있는 데이터 범위 안에서만 움직입니다.
운영 환경에 맞춰 상용 AI 모델과 로컬 LLM 을 연계합니다. 인터넷 연결이 제한된 망분리 환경에서는 로컬 LLM 으로 내부 데이터를 조회 · 분석합니다. 반도체처럼 폐쇄망이 기본인 현장을 위해 경량 언어모델과 SQL 특화 모델을 결합한 하이브리드 AI 엔진도 개발하고 있습니다.
프롬프트 체계가 MCP 기반으로 모듈화돼 있어, 바뀐 업무의 모듈만 갈아 끼웁니다.
