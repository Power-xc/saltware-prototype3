HOW IT WORKS

요청이 밖으로 나가기 전에
세 단계를 거칩니다

사용자가 보낸 프롬프트와 파일은 외부 AI 에 닿기 전에 Sapie-Guardian 을 먼저 지납니다. 무엇이 들었는지 찾고 정책대로 처리한 다음 그 결과를 남깁니다.

01프롬프트 · 파일 검사

문제직원이 프롬프트에 고객 주민등록번호를 붙여 넣습니다

탐지

외부 AI 보다 Sapie-Guardian 이 요청을 먼저 받습니다. 개인정보 패턴과 기밀 키워드를 찾고, 경량 언어 모델(sLLM)이 앞뒤 문맥을 읽어 정해 둔 낱말로는 잡히지 않는 민감정보까지 가려냅니다.

  • 첨부 파일은 HWP · HWPX · DOC · DOCX · PPT · PPTX · XLS · XLSX · PDF · ODT 열 가지 형식의 내용까지 읽습니다.
  • ChatGPT · Claude · Gemini · Perplexity 같은 웹 서비스와 Claude Code · Gemini CLI 같은 AI 코딩 도구로 가는 요청을 함께 봅니다.

3겹탐지 계층 — 개인정보 패턴 · 키워드 · 문맥(sLLM)

02정책 처리

문제첨부한 계약서가 그대로 외부 모델로 넘어갑니다

가림 · 차단

찾아낸 내용은 관리자가 정한 정책대로 처리합니다. 민감한 부분만 가리거나(마스킹) 다른 값으로 바꿔(치환) 보낼 수 있습니다. 위험하다고 판단한 요청은 외부로 넘기지 않습니다.

  • 막힌 사용자에게는 까닭을 적은 안내가 바로 뜹니다. 안전한 요청은 평소처럼 흘러갑니다.
  • AI 가 돌려준 응답에 기밀 · 민감정보가 섞여 있어도 거릅니다.

5가지정책 처리 — 허용 · 차단 · 마스킹 · 치환 · 로깅

03로그 · 감사

문제사고가 나도 누가 무엇을 보냈는지 남아 있지 않습니다

기록

사용자 입력과 AI 응답, 위반 이력과 정책 적용 결과를 모두 남깁니다. 관리자 화면에서 부서 · 사용자별 위반 현황과 자주 걸리는 키워드를 봅니다.

  • 누가 무엇을 보냈고 무엇을 돌려받았는지가 감사 근거로 남습니다.
  • 쌓인 로그로 AI 보안 리포트를 만듭니다.

ADMIN CONTROLS

무엇을 막을지는
관리자 화면에서 정합니다

탐지와 처리의 기준은 제품 설정입니다. 정책 · 입력 제한 · 접근 제어 · 모니터링 · 감사 기록 다섯 가지를 한 화면에서 다룹니다.

  • 01POLICY

    허용 · 차단 기준

    기업 보안 기준을 정책으로 정의해 전사 AI 사용 환경에 똑같이 적용합니다. 부서 · 사용자마다 쓸 수 있는 AI 서비스와 범위를 나눕니다.

    • 부서 · 사용자별 정책
    • 금칙어 · 위험 패턴
    • 마스킹 · 치환 규칙

  • 02INPUT LIMITS

    입력 · 업로드 제한

    파일 크기와 프롬프트 글자 수에 상한을 둡니다. 민감정보가 한꺼번에 대량으로 넘어가는 것을 미리 막습니다.

    • 파일 크기별 제한
    • 프롬프트 글자 수 제한
    • 키워드 제한

  • 03ACCESS

    AI 서비스 접근 제어

    기업형 AI 서비스는 워크스페이스 ID 로 조직의 계정인지 확인해, 승인된 환경에서만 쓰게 합니다.

    • 워크스페이스 ID 기반 인증
    • 조직 단위 권한

  • 04MONITORING

    대시보드 · 알림

    AI 사용 현황과 보안 이벤트를 한 화면에서 봅니다. 정책 위반과 이상 행위를 찾으면 담당자에게 알립니다.

    • 실시간 위협 통계
    • 위반 키워드 분석
    • 주요 위반 유형

  • 05AUDIT

    감사 기록 · 리포트

    누가 언제 어떤 AI 에 무엇을 보냈는지 남깁니다. 로그로 AI 보안 리포트를 만들어 감사 대응 근거로 씁니다.

    • 사용자 입력 · AI 응답
    • 위반 이력 · 정책 적용 결과
    • 로그 내보내기

HOW WE WORK

도입 절차

구축 방식과 사용자 규모, 분석 대상과 통제 범위를 먼저 정하면 범위와 비용이 정해집니다.

  1. 01

    도입 문의

    적용 목적과 대상 범위, 지금 쓰는 생성형 AI 같은 기본 정보를 확인합니다.

  2. 02

    요구사항 협의

    보안 요구사항과 환경을 맞춥니다. 지킬 데이터와 보호 수준, 인프라 방식과 연계 대상을 정합니다.

  3. 03

    콘솔 준비

    관리자 계정을 만들고 콘솔에서 탐지 정책과 모델을 설정합니다.

  4. 04

    연동과 사전 테스트

    기존 프록시와 인증 체계에 잇습니다. 차단과 마스킹이 제대로 도는지 사용자 테스트로 봅니다.

  5. 05

    운영 정책 이관

    운영 정책을 확정해 넘기고 사용자 교육과 가이드라인을 드립니다. 이후 운영 데이터를 보며 정책을 고도화합니다.

제품 소개서 요청하기
웹 프록시는 URL · 도메인 · 세션 단위로 접속을 통제하고, 기존 DLP 는 이메일 · 문서 · 웹 업로드가 중심입니다. Sapie-Guardian 은 생성형 AI 로 가는 프롬프트 · 첨부 파일 · 응답의 내용을 봅니다. 기존 프록시를 대체하지 않고 그 뒤에 한 층으로 붙습니다.
ChatGPT · Claude · Gemini · Perplexity 같은 웹 서비스와 Claude Code · Gemini CLI 같은 AI 코딩 도구입니다. 다른 서비스와 파일 형식은 요청에 따라 더해 구성합니다.
주민등록번호 · 외국인등록번호 · 여권번호 · 운전면허번호 · 계좌번호 · 카드번호 · 전화번호 · 이메일 같은 개인정보는 기본으로 찾습니다. 고객 상담 내역, 계약서 · 사업계획서 같은 사내 문서, 소스코드 · API Key 같은 개발 정보는 조직의 정책과 키워드로 정합니다. 개인정보보호법 · 정보공개법 같은 국내 규정을 반영했습니다.
구축형은 내부망 · 폐쇄망에 설치해 데이터를 밖으로 내보내지 않고 검증합니다. 망 분리 구조와 보안 정책을 먼저 확인하고 기존 게이트웨이 · 프록시 · 인증 체계와 잇습니다. 클라우드형과 하이브리드형도 있습니다.
도입 전 검증(PoC)에서 기준을 먼저 정합니다. 탐지 정확도와 오탐 허용 수준, 차단 · 마스킹 · 치환의 동작, 응답 시간, 사용자 업무 흐름에 주는 영향입니다. 출시 당시 인터뷰에서 개발팀은 탐지에 걸리는 시간을 3초 이내로 밝혔습니다(바이라인네트워크 2025.10.01).
기본 구축은 약 2주입니다(제품 소개서 v2.0 기준). 연동할 생성형 AI · 파일 형식을 더하거나 고객 정책을 반영하는 범위에 따라 달라집니다.
기업용 AI 데이터 플랫폼 Sapie-ADP 에 가드레일로 들어가, 기업이 정한 보안 · AI 이용 정책대로 AI 활용을 통제합니다. Sapie-Guardian 만 따로 도입할 수도 있습니다.
구축 방식 · 사용자 규모 · 분석 대상 · 통제 범위에 따라 달라집니다. 클라우드형은 사용 기간 · 트래픽 · 모델 사용량을 기준으로 셉니다.
